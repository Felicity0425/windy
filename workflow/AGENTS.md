# LLM Wiki Schema For Codex

你正在维护一个基于 Markdown 的持久化知识库 Wiki。你的职责不是一次性回答问题，而是持续把原始资料编译成结构化、可交叉引用、可长期维护的 Wiki。

## 仓库结构

- `raw/`
  - 原始资料层，只读不改
  - 可以新增资料文件或附件，但不要改写既有资料内容
- `wiki/`
  - 知识页层，由你维护
  - 包含资料摘要页、实体页、概念页、工作流页、综合分析页
- `AGENTS.md`
  - 当前仓库的 schema
  - 规定目录、页面格式和 ingest/query/lint 工作流
- `skill/SKILL.md`
  - 这套方法的 Skill 备份说明

## 总原则

1. 把 `raw/` 视为事实来源，把 `wiki/` 视为编译产物。
2. 导入新资料时，优先更新既有页面，而不是重复创建近义页面。
3. 页面之间尽量用 `[[wikilink]]` 交叉引用，形成网络。
4. 发现矛盾时明确标注，不要静默覆盖旧说法。
5. 每次 ingest 都必须更新 `wiki/index.md` 和 `wiki/log.md`。
6. 有价值的 query 结果可以沉淀为新的 Wiki 页面，而不是只停留在对话里。

## 页面类型与命名

- 资料摘要页：`source-{关键词}.md`
- 实体页：`{实体名}.md`
- 概念页：`{概念名}.md`
- 工作流页：`{场景}-workflow.md`
- 综合分析页：`{主题}-analysis.md`

如果一个主题已经有页面，优先更新原页，不要新建语义重复页。

## Frontmatter 约定

### 资料摘要页

```yaml
---
tags: [source-summary, 领域标签1, 领域标签2]
source: "原文标题"
author: 作者名
date: YYYY-MM-DD
url: "原始链接"
---
```

### 实体页

```yaml
---
tags: [entity, tool]
type: entity
---
```

### 概念页

```yaml
---
tags: [concept]
type: concept
---
```

### 工作流页

```yaml
---
tags: [concept, workflow]
type: concept
---
```

### 综合分析页

```yaml
---
tags: [analysis]
type: analysis
---
```

## 页面内容约定

### 资料摘要页应尽量包含

- 来源信息
- 核心观点
- 关键数据、案例或证据
- 注意事项、局限、矛盾点
- 相关概念
- 指向实体页和概念页的 `[[wikilink]]`

### 实体页应尽量包含

- 一句话定义
- 核心特点
- 在不同场景中的角色
- 来自多份资料的案例与补充
- 来源

### 概念页和工作流页应尽量包含

- 概念定义
- 结构或流程
- 与其他概念的关系
- 案例或适用场景
- 来源

## Ingest 工作流

当用户说“导入”“处理这份资料”“添加到知识库”时：

1. 读取 `raw/` 中指定资料。
2. 提取其主题、核心观点、关键实体、关键概念、案例、数据和限制。
3. 创建资料摘要页 `wiki/source-xxx.md`。
4. 查找是否已有相关实体页、概念页、工作流页。
5. 创建缺失页面，并更新已有页面。
6. 在所有相关页面间补充 `[[wikilink]]`。
7. 更新 `wiki/index.md`，把新页按类别登记。
   - 如果某个分类仍有 `_暂无_` 占位行，首次录入真实页面时删除该占位行。
8. 在 `wiki/log.md` 追加日志，记录：
   - 来源
   - 新建页面
   - 更新页面
   - 关键要点
   - 与已有知识的关联
   - 矛盾或补充关系

典型的一次中等规模 ingest 会触及 5 到 8 个文件；较复杂资料可能更多。

## Query 工作流

当用户基于知识库提问时：

1. 先读取 `wiki/index.md`，确定相关页面。
2. 再深入读取具体页面。
3. 综合回答，并在回答中尽量引用具体页面。
4. 如果这次回答形成了稳定且有复用价值的分析，主动判断是否应沉淀为新的 `*-analysis.md` 页面。

## Lint 工作流

当用户说“检查知识库”“维护一下”“做一次 lint”时：

1. 检查互相矛盾的页面内容。
2. 检查被新资料取代但尚未更新的旧说法。
3. 检查没有入站链接的孤立页面。
4. 检查被多次提及却缺少专页的重要实体或概念。
5. 检查缺失的交叉引用。
6. 标记值得继续补充的数据空白和资料方向。

## 编辑规则

- `wiki/log.md` 按时间顺序追加，不回写历史记录。
- `wiki/index.md` 是内容目录，不写长篇正文。
- `raw/` 中资料不可重写，只能新增。
- 不要把“导入结果”只写进一页摘要里，要同步更新相关实体页和概念页。
- 如果多篇资料表达相似观点，要在页面中显式标注共同主题。
- 如果多篇资料观点冲突，要在页面中显式标注矛盾来源。

## 回答风格

- 默认先用已有 Wiki 页面回答，避免脱离知识库自由发挥。
- 知识库里没有的内容，要明确说是新推断或待补资料。
- 当用户请求“重新整理”“汇总”时，优先考虑生成或更新 Wiki 页面，而不是只在聊天里回答。
