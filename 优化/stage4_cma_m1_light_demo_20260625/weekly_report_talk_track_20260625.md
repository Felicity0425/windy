# 周报汇报话术（2026-06-25）

## 一、开场总述

这周我主要做的不是继续盲目调参，而是先把 Stage4 后续优化最关键的前置问题梳理清楚。整体上，我完成了四件事：第一是把 `CMA/CRA40` 再分析数据做了系统审计；第二是把背景独立性，也就是 `P0-LEAK` 这个风险点查清楚；第三是做了误差地板估计，量化系统理论上还有多大优化空间；第四是跑通了 `S4-CMA-M1` 轻量 demo，并开始切换到 `GFS forecast` 独立背景路线。

## 二、本周为什么先做这几件事

我这周之所以没有直接推进 `OI`，原因是如果背景本身并不独立，那后面很多结论都会不可靠。  
这里有两个关键概念：

第一，`OI`，也就是最优插值，本质上是把“背景场”和“观测”按权重融合，得到一个更好的分析场。  
第二，`innovation`，也就是创新量，定义为 `观测 - 背景`，它用来衡量背景到底偏了多少。

但是要成立，前提是背景不能偷看我最后拿来评估的 holdout 观测。如果背景里已经同化了同一批飞机风，那再去算创新量，就会把“偷看过真值”的背景误当成高质量背景，所以这是我本周优先审计的原因。

## 三、本周完成的第一块：`P0-CMA`

我先把本地 `CMA/CRA40` 数据做了完整校验，新增了 `verify_cma_grib.py`。  
这个脚本做了三件事：

1. 检查文件是不是能读。
2. 检查变量和层数是不是齐全。
3. 检查时间覆盖能不能覆盖我当前 `200` 帧和 `5614` 帧实验。

结果上，本地 `CMA` 数据共有 `773` 个文件，覆盖 `2026-01-23 00Z` 到 `2026-02-24 00Z`，抽样读取 `18/18` 成功。风场主变量是完整的，唯一已知缺口是 `2026022012` 缺 `GPH`。所以结论是：这批 `CMA` 数据本身是可用的，数据质量不是当前瓶颈。

## 四、本周完成的第二块：`P0-LEAK`

我把 `CMA` 官方页面、用户手册和本地文件命名都对了一遍。现在可以明确：

1. `NAFP_CRA40_FTM_6HOR` 属于 `CMA-RA` 再分析产品。
2. 它使用的是三维变分同化。
3. 所以它不是纯预报背景，而是分析/再分析产品。

这意味着什么？  
意味着它可以拿来做显示层补全，但**不能直接宣称是严格独立背景**，也就不能直接拿来做正式的 `OI` 和 `innovation` 结论。

我还审计了自己的数据源，比如 `amdar`、`turb`、`location` 以及 Stage2、Stage3 派生结果。结论是：这些数据当然可以继续作为训练观测，但它们本身不能替代独立背景。因为它们和我要评估的观测链是同源的。

所以 `P0-LEAK` 这一步的真正成果是：我把一个原来不明确的问题，变成了有证据、有边界的结论。  
当前可以安全做的是 `M1 display-only`；当前不能直接做的是 `CMA` 驱动的 `OI` 正式结论。

## 五、本周完成的第三块：`P0-FLOOR`

我这周还新增了误差地板估计脚本 `centralized_stage4_error_floor_estimate.py`。  
它的目的很简单：先估计现在系统理论上大概还能优化多少，不然很容易把大量时间耗在几乎不可能再降的误差上。

结果是：

- 当前 baseline vector RMSE 是 `14.769`
- 我估计的 local proxy floor 大概是 `11.113`
- 两者之间还有 `3.656 m/s` 左右的空间

也就是说，系统确实还有优化空间，但不是无限大。  
最关键的是高空，也就是 `12km+` 这一层：

- 现在 `12km+` 的 RMSE 是 `19.918`
- 它的 proxy floor 大概是 `14.169`

这说明下一步最值得打的不是全局瞎调，而是高空稀疏区。

## 六、本周完成的第四块：`S4-CMA-M1` 轻量 demo

这周我没有直接给 `200` 帧全量生成大量 `npz`，而是按更稳妥的方式做了两层实验。

第一层，是 `200` 帧 `metrics-only` 主跑，使用 `25` 路并行。  
目的就是先确认当前 baseline 能不能稳定复现。

结果是：

- `vector RMSE = 14.7690`
- `vector MAE = 6.8545`
- `frame mean RMSE = 8.2243`
- `12km+ RMSE = 19.9177`
- `light wind RMSE = 5.1959`

这些数和原 baseline 基本一致，说明这次轻量化跑法是可靠的。

第二层，是只选 `6` 个代表帧做 `M1 display-only weak background fill`。  
这里要强调一个概念，`display-only` 的意思是背景只用于显示层补全，不进入官方评估的 `recon_u / recon_v / recon_conf / recon_mask`，所以不会污染官方 RMSE。

这 `6` 个代表帧的结果是：

- 背景填充比例大概在 `97.72%` 到 `98.49%`
- 平均大约 `98.16%`
- 填充区域显示置信度上限都被压到 `0.20`

这说明 `M1` 这条产品链已经跑通了：  
它能把大面积空白区补成完整风场图，同时又能明确告诉使用者“这里是低置信背景，不应被当作高可信重构”。
